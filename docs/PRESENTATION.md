# Two-day presentation guide

## The promise

“Umama enters client information once, reviews the extracted facts, develops six LinkedIn deliverables, and prepares a report after approval. The workspace organizes repetitive work while keeping her judgment in control.”

Avoid unsupported time-saving percentages, accuracy guarantees, real-client claims and implying that the demo is live Gemini generation.

## Day 1: establish a reliable demonstration

1. Run the local server and open the workspace in Chrome or Edge.
2. Use Settings → Reset fictional demo.
3. Rehearse the six-minute flow below.
4. Build and publish the public demo if your GitHub account is ready.
5. Configure the private Google deployment only if you have the owner account and Gemini access. Do not make live setup a dependency for the presentation.

## Day 2: verify and rehearse

1. Re-run the tests, restart the preview, and verify it at the intended screen resolution.
2. If presenting live Google mode, finish every live smoke check in SETUP.md.
3. Keep the local demo and a downloaded sample report available as a fallback.
4. Reset fictional demo data before the meeting.
5. Explain what is implemented and what still needs account configuration.

## Six-minute walkthrough

| Time | Show | Say |
| --- | --- | --- |
| 0:00–0:45 | Overview | “Every client has a next step. The dashboard shows actual saved progress.” |
| 0:45–1:30 | New client → enter a fictional name → Use sample notes → confirm permission → Create | “Raw notes become a client record. Nothing is posted to LinkedIn.” |
| 1:30–2:15 | Extract information → review one fact | “Extraction is not verification. Each claim has a source and an explicit review decision.” |
| 2:15–3:30 | Open seeded Ayesha Khan → AI workspace → Headline → Generate | “This presentation uses deterministic templates. Live mode sends reviewed facts to Gemini through the private server.” |
| 3:30–4:15 | Edit a headline → Save draft → Approve | “Each save is a version. Approval requires a human accuracy check.” |
| 4:15–5:15 | Final report → Draft HTML | “The report assembles the saved deliverables. Final delivery is blocked until all six modules are approved.” |
| 5:15–6:00 | Version history and Settings | “Live mode uses Google sign-in, a private Sheet, a private Drive folder and a server-held API key.” |

For a full final-report demonstration, generate and approve all six modules for seeded Ayesha before the meeting. Her demo facts are already marked verified as fictional fixtures. Use the approval checkbox only after reviewing the content. The final HTML opens in a browser; use Print → Save as PDF if you need a local PDF. Live mode generates the PDF in Drive.

## Honest answers to likely questions

- **Is this using real AI today?** Demo generation uses templates. Live Gemini integration is implemented but needs owner credentials and a live verification run.
- **Can it publish directly to LinkedIn?** No. Phase 1 creates reviewed deliverables for manual use.
- **Can clients log in?** No. It is a private admin workspace.
- **Does it verify claims online?** No. It traces intake quotations and records the admin's verification evidence.
- **Is it ready for real client use?** The demo is ready to present. Real client use requires the documented live setup, smoke tests and privacy/retention decisions.
- **What is the public portfolio?** A separate future website. It does not share client storage or admin secrets.

## Demo recovery

Use Settings → Reload saved workspace after a connection or stale-version message. Copy unsaved text first. Settings → Reset fictional demo restores the original three clients. If live AI fails, continue with existing drafts or return to the local demonstration; do not claim a template response came from Gemini.
